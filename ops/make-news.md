# make-news：ニュースアカウント（@nanikore.tsushin・インスタのみ）の見出しとキャプションを書く（today.mjs に ■ make-news が出たとき。Opus のサブエージェント）

書く本数は today.mjs の行のとおり（品質を落として数を合わせない。良い候補が足りなければ少なくてよい）。決めごとは docs/NEWS.md の ネタと文章の決めごと。承認は挟まず、そのままインスタに出る。

## 手順
1. 作業フォルダの moshimo-lab で `git fetch -q origin news-data && git worktree add -q ../w-news-data origin/news-data -B news-data`（以下 ../w-news-data で作業。news-data は main とは別のブランチ。main には何も足さない）。
2. `candidates.json` を読む。items が候補（title・site・url・text＝元記事の本文の先頭2,500字・imgs＝写真の候補）。`queue/` にまだある回、`done.txt` と `failed/` に載っている元記事URLは使わない（同じ話を2回出さない。タイトルが違っても中身が同じ話も避ける）。
3. 候補を全部読んで、日本の20〜40代が思わず友だちに送りたくなる話を選ぶ。伸びる型：身近な物の知らなかった秘密／動物・自然の珍しい光景／人のやさしさ・恩返しの実話／一般人のありえないうっかり／ギネス記録・世界に1つの物・とんでもない作品／写真1枚で伝わる科学の意外な事実。同じ型・同じ媒体が続かないように混ぜる。いちばん伸びるのは 身近な物の秘密（PS5コントローラーの持ち手は4万個の○△×□、メジャーの先がグラグラなのはわざと のように、誰でも手元で確かめられるもの）と 一般人のありえないうっかり・強運（柵の杭だと思ったら逃げた大蛇、給油機の故障で宝くじ3億円）。この2つを1日の半分以上にする。いい話・かわいい動物だけの回はパンチが弱いので score を下げる。
   - 候補にパンチのある話が足りないときは、自分で WebSearch して探してよい（UPI Odd News、News of the Weird、身近な物の隠れた機能の解説記事など。元記事は1〜2週間以内の話か、いつ読んでも驚ける物の秘密）。その場合は key を "web"、source に元記事の url・site、imgs にその記事に載っている写真のURLを配列で書く（その記事の写真だけ。別サイトの写真を混ぜない。WebFetch で記事を開いて写真のURLを確かめる）。
4. 出さない話（必ず外す）：人が亡くなる・大けが・残酷な事件、性犯罪、子どもや動物への虐待、自殺、災害の被害、政治・選挙・宗教・戦争・民族の対立、特定の国や人種を笑いものにする話、一般人を犯罪者扱いする話、芸能ゴシップ・炎上、医療・健康・お金で真に受けると害が出る話、日本のニュース、写真がないと伝わらない話（imgs が人物の顔写真だけ・ロゴだけになりそうなもの）、作品紹介・まとめ記事（○選・○枚の写真）、今日は何の日の記事。
5. 1本ずつ書く。事実は text に書いてあることだけ（数字・地名・年・人数は記事どおり。足りなければ url を WebFetch で開いて確かめてよい。確かめられないことは書かない・盛らない。不確かなことは〜とされています）。一般人の名前は出さない（男性・20代の女性 など）。人を見下さない。
   - title：投稿画像の見出し。2〜3行の配列、1行14文字以内（記号も1文字）。1行目で状況、最後の行（黄色になる）でオチや驚きを言い切る。嘘や大げさな言い方はしない。絵文字・ハッシュタグなし
   - pages：2枚目からのスライドの文（キャプションを読まない人がスライドだけで話が全部わかるように）。3〜4枚、1枚40〜80字。何が起きたか → 詳しく → 意外なところ → 結末 の順に話を進める。見出しと同じことを繰り返さない。です・ます にせず言い切りの文（〜した。〜だった。）
   - punch：最後のスライドに黄色で大きく出すオチのひとこと（12字以内で1行に収める。例 犬だけが気づいていた／直したら、壊れます）
   - coverImg・pageImg：どの写真をどこに出すか。候補の imgs の番号（1から）。ファイル名（reunites-with-mom、swimming など）を見て話に合う写真を選ぶ。coverImg は1枚目、pageImg は pages と同じ数の配列で、写真を出さないページは 0（そのページは写真をぼかした背景に文字だけになる）。同じ写真は2回使わない。オチが写った写真（再会・結末）は1枚目か最後の方に回し、話より先にネタバレしない。2枚組・赤丸つき・文字入りの画像は1枚目にしない。わからなければ書かなくてよい（自動で順番に出る）
   - body：キャプション本文。です・ます調、280〜450字、4〜6段落（段落の間は空行）。1文目で何が起きたかを言い切る（前置きなし）。真ん中で詳しい事実と日本人に伝わる補足。最後の段落は軽いひとことで締めて絵文字を1つだけ。ハッシュタグなし
   - ask：コメントしたくなる問いかけ1行（20字以内）
   - hashtags：3〜4個（# なし）。内容に合う、日本で実際に使われている言葉（海外ニュース・雑学・動物好きな人と繋がりたい など）。1つ目のアカウント名のタグは自動で付くので入れない
   - category：動物・自然／身近な物の秘密／人のやさしさ／うっかり・珍事件／記録・発明／科学 のどれか
   - score：シェアされそう度 1〜10（7未満なら書かない）
6. `queue/<番号>.json` に書く。番号は n＋今の日本時間の年月日時分10桁（例 2611090923）＋連番1〜9（例 n26110909231）。形：
   `{"id":"n26110909231","key":"c3","source":{"url":"<候補の url>","site":"<候補の site>"},"title":["",""],"pages":["","",""],"punch":"","coverImg":1,"pageImg":[2,0,3],"body":"","ask":"","hashtags":[""],"category":"","type":"<伸びる型>","score":8}`
   書いたら見直す：見出しの文字数、スライドの文（3〜4枚・1枚40〜80字・スライドだけで話がわかるか）、本文の字数（280〜450字）、事実が text と合っているか、出さない話に当たっていないか。
7. 全部書けたら `cd ../w-news-data && git add queue && git commit -m "news: <本数>本" && git pull -q --rebase origin news-data && git push origin HEAD:news-data`（commit の最後に Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>）。
8. `gh api -X POST repos/oishi-thomaz/moshimo-lab/actions/workflows/news-build.yml/dispatches -f ref=main` を1回だけ（写真を取ってきて画像を作り、投稿サーバーに送る。終わるのは待たない。動かなくても3時間ごとに自動で拾う）。
9. `git worktree remove ../w-news-data`。

最後の返答：書いた番号と見出し（1行）と媒体、外した候補の数と主な理由。
